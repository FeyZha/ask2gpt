# Ask2GPT 体验样例

这里的 `insight-board.ts` 是一段完全离线的 TypeScript 示例代码：它只在内存中把用户反馈归纳为洞察，不读取文件、不访问网络，也不需要密钥。

代码包含正常业务逻辑，也保留了缓存、数据规范化、可变性和时间表示等可讨论点。体验时先不要看答案，直接让 Ask2GPT 帮你分析。

## 第一次体验：解释选区

1. 在 VS Code 中打开 `insight-board.ts`。
2. 选中 `summarize` 方法。
3. 打开黄色灯泡，选择“将当前选区添加到 Ask2GPT”。
4. 发送：

> 请用简单语言解释这段代码的数据流，并分析它的时间复杂度。

回答应只解释所选代码，不读取项目中的其他文件。

## 第二次体验：分析问题

仍然选中 `summarize` 方法，可以继续问：

> 这段缓存设计可能在哪些调用顺序下返回不符合预期的结果？请给出两个具体例子，但不要修改代码。

也可以问：

> 重复标签、负数 limit 和调用方修改返回数组时，分别会发生什么？请按影响程度排序。

## 第三次体验：比较方案

附加当前文件，然后问：

> 在这个场景中，`Map<string, Bucket>` 与 `Record<string, Bucket>` 各有什么取舍？

或者：

> 如果要支持“最近 30 天的反馈”，继续使用 ISO 字符串比较和先转换为时间戳，各有什么优缺点？

## 第四次体验：整文件理解

附加当前文件，发送：

> 请从职责划分、数据所有权和缓存一致性三个角度评价这个类。只做分析，暂时不要给修改代码。

你还可以测试多轮对话：

1. `先列出你认为风险最高的两个问题。`
2. `为什么第一个问题比第二个更重要？`
3. `请比较三种可选设计，不需要写实现。`

## 第五次体验：生成工程方案

附加任意选区后发送：

> 请给出修复这段代码的具体补丁，并列出应执行的测试命令与预期结果。

这个请求应与普通问题一样发送到当前 ChatGPT 会话，不出现本地拦截提示或其他产品的任务模板。

## 体验检查

- 发送前能看到文件名、语言、行号、字符数和代码预览。
- 发送成功后，待发送上下文被清空。
- 回答支持 Markdown、列表和代码块。
- 多轮问题保持在同一个远端 ChatGPT 会话中。
- Ask2GPT 不修改本示例或项目中的任何文件。
